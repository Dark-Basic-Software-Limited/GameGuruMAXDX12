C2 IS AMENDED, carried forward verbatim from tools/prereg_0922_3.82.txt, which was written before
3.82 and whose sweep never ran:

  3.81d/3.82 stop the old-file performance downgrade from overwriting settings a level's own
  visuals.ini states explicitly. MOST SHIPPED DEMOS HAVE PRE-2024 VISUALS FILES, so any demo whose
  old file explicitly states shaderlevels.terrain/entities/vegetation/lighting now KEEPS its stated
  level instead of being stamped LOW. Shaderlevels drive vegetation and object detail, so POLYS can
  legitimately move.

  PREDICTION: POLYS moves ONLY on demos whose embedded visuals.ini contains a shaderlevels key.
  A move on a demo whose file states no shaderlevels key is NOT explained by this change and is a
  real finding to investigate, not to rationalise.

C2 IS **NOT** AMENDED FOR 3.84c, and this is the falsifiable part. 3.84c clears a wholly-degenerate
tangent stream so CreateRenderData regenerates it. It replaces one XMFLOAT4 per vertex with another
XMFLOAT4 per vertex:

  POLYS  MUST NOT MOVE on any demo. Triangle count is untouched by a tangent frame.
  VRAM   MUST NOT MOVE beyond run-to-run scatter. The buffer already existed; only its contents
         change. If VRAM rises materially on a character-heavy demo, the fix is allocating a
         SECOND stream rather than refilling the first, and that is a defect.
  LOOK   MAY change - correct normal mapping where it was previously dead. Expected on characters.
