## Addendum (same day, ~16:30): the sculpt-grass bug — FIXED, and one more tripwire triaged

**User-reported after the audit:** sculpting a hill made all local grass disappear
permanently. Root-caused in ~15 minutes using the audit era's own instruments
(hair-kill tracer + GRASS_* counters): in-place chunk regen recursively kills the attached
grass child under the SAME entity id, so 1.85's entity-identity detector never fires and the
grass bookkeeping holds a dead entity forever. Fix (game `1e9fb978`): liveness validation in
the ProcessGrassChunks scan — dead records are dropped, the chunk marked bare, and stamped so
regrowth waits for the stroke to settle. Verified sculpt/undo/re-sculpt: 6/6/6 systems,
518,000 strands restored exactly each cycle; density gate baseline 6.877%/0.957 vs fixed
6.846%/0.952 (the broken build measured 0.019% — a 99.7% grass wipe at the user's camera).
New counter: GRASS_EXTKILLS. Rule reinforced (third occurrence of this shape): a map record
is NOT proof the entity exists — validate liveness, never identity alone.

**Tripwire triage (found during the hunt):** `Files/applytransform_garbage.txt` — 12 MB,
13,086 events since 2026-07-18. NOT a regression: it is the parrot-fix decompose guard
healing sheared model-node transforms on every load, exactly as designed, with zero runtime
events. The unbounded synchronous logging was the defect — capped at 64 events/session
(engine `0f6165a7`). Note for future checks: tripwire files land in the game's `Files/` CWD,
not next to the exe.
